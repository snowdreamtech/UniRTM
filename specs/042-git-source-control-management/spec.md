# 功能规范：Git 源代码管理系统 (Source Control Management)

## 1. 背景与目标 (Background & Goals)

UniRTM 作为一个全功能现代化 Web/桌面端一体化工作台，已经具备了完备的资源管理器、多标签代码编辑器 (Monaco Editor)、终端多会话与任务执行系统。然而，开发者日常编码工作流程中必不可少的核心环节是**代码版本控制 (Git)**。

本功能的目标是**深度对齐 Visual Studio Code 的源代码管理 (SCM) 体验**，为用户提供一个无需切换离开 IDE 即可完成日常代码版本审查、暂存、撤销、比对与提交的完整闭环系统。

---

## 2. 用户故事 (User Stories)

- **US-1 (变更洞察)**：作为开发者，我希望在活动栏 (Activity Bar) 一目了然地看到当前仓库有多少待处理的修改文件，以便掌控工作区状态。
- **US-2 (暂存与撤销)**：作为开发者，我希望能够对单个文件或全部文件执行“暂存 (Stage)”、“取消暂存 (Unstage)”或“放弃更改 (Discard)”，以便精确组织每一次提交。
- **US-3 (代码提交)**：作为开发者，我希望在 SCM 侧边栏输入提交信息，通过快捷键 `Ctrl+Enter` 或点击提交按钮，快速生成规范的 Git Commit。
- **US-4 (代码审查与差异对比)**：作为开发者，我希望点击任一修改的文件时，能够直接打开 Monaco Diff Editor，以“并排 (Side-by-side)”或“内联 (Inline)”形式查看逐行增删高亮差异。
- **US-5 (分支切换与同步)**：作为开发者，我希望能够查看当前分支、切换本地/远程分支，以及了解当前分支与远程上游 (Upstream) 的领先 (Ahead) 和落后 (Behind) 状态。

---

## 3. 功能需求矩阵 (Functional Requirements)

### 3.1 核心 SCM 侧边栏与活动栏
- **FR-1.1 (活动栏入口)**：在活动栏（紧随资源管理器）提供 `workbench:scm` 图标，右上角显示未处理文件总数 Badge。
- **FR-1.2 (分支状态条)**：顶部显示当前活跃分支名称、上游同步指示器（如 `↓0 ↑1`）、状态刷新按钮以及分支切换浮层。
- **FR-1.3 (提交控制区)**：多行提交信息输入框，支持 `Ctrl+Enter` / `⌘Enter` 提交快捷键及提交按钮状态反馈。
- **FR-1.4 (暂存区与工作区分组)**：
  - 分离展示“暂存的更改 (Staged Changes)”与“更改 (Changes)”。
  - 每个文件条目展示文件图标、文件名、相对目录、状态徽标（`M` 修改、`A` 新增、`D` 删除、`U` 未跟踪、`R` 重命名）。
  - 悬停快捷按钮：在编辑器中打开、放弃更改、暂存/取消暂存。

### 3.2 Monaco 差异比对编辑器
- **FR-2.1 (双栏/内联对比)**：利用 Monaco DiffEditor 渲染原始文件 (Original/HEAD) 与当前修改 (Modified)，保持语法高亮与语法树解析一致。
- **FR-2.2 (模式切换)**：支持在并排比对 (Side by Side) 与内联比对 (Inline) 之间无缝切换。
- **FR-2.3 (顶部操作栏)**：在 Diff 视图顶部提供文件路径、状态标识、快速暂存/取消暂存按钮、放弃更改按钮及“在代码编辑器中打开”按钮。

### 3.3 后端 REST API
- **FR-3.1 (`/api/git/status`)**：输出解析后的分支名、上游、ahead/behind 计数、staged 文件列表、unstaged 文件列表与 untracked 文件列表。
- **FR-3.2 (`/api/git/stage` & `/api/git/unstage`)**：接收特定文件路径数组或全部暂存/取消暂存指令。
- **FR-3.3 (`/api/git/discard`)**：撤销工作区修改或移除未跟踪文件。
- **FR-3.4 (`/api/git/commit`)**：支持标准提交及 `--amend` 修正提交。
- **FR-3.5 (`/api/git/diff`)**：接收文件路径及 staged 标志，返回 original 和 modified 纯文本内容供比对器使用。
- **FR-3.6 (`/api/git/branches` & `/api/git/checkout`)**：分支枚举与检出切换。

## 4. 非功能性需求 (Non-Functional Requirements)

- **NFR-1 (安全隔离)**：所有 Git CLI 调用必须在工作区当前根目录限制内执行，防范目录遍历与注入风险。
- **NFR-2 (纯离线环境)**：Monaco 离线加载，不依赖任何公网 CDN。
- **NFR-3 (双端一致性)**：生产环境 Go 内嵌二进制与开发环境 Vite Dev 中间件实现 100% 相同的数据契约与行为表现。
- **NFR-4 (性能与防抖)**：状态拉取与差异加载需具备并发保护与防抖机制，避免文件频繁变动引起界面卡顿。
