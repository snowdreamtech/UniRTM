# 需求规范：全局按钮设计系统与交互体验统一 (Button Design System & UX Unification)

## 1. 概述与背景
经过前序多轮迭代，UniRTM 的 Web UI 已经完成对配置核心（工具、环境、任务、钩子、别名、市场、常规设置等）的 100% 可视化覆盖。
但在界面快速拼装过程中，各个页面的按钮样式缺乏集中治理，呈现出明显的体验碎片化现象：
- **形式不一**：有的按钮是纯文字、有的是纯图标、有的是图文混排，甚至存在裸手写字符（如 `✕`、`↺`、`AA`）；
- **层级混乱**：核心主操作、辅助次要操作、行内高密度小操作、危险删除操作之间视觉层级不清晰；
- **度量衡不齐**：不同视图中类似功能的按钮尺寸、圆角、内边距、Hover 反馈及 Active 按压动效各不相同。

本特性的目标是建立一套通用的**全局按钮设计系统（Action Design System）**，并在全站各视图中分步统一重构，打造统一、精致、符合工业级直觉的操作体验。

---

## 2. 用户场景与体验目标

### 2.1 场景 1：顶层/工具栏主操作（Primary Actions）
- **痛点**：过去不同模块工具栏按钮高度、内边距、图标大小不一；
- **目标**：用户一眼即可辨识模块的核心创建或执行入口（如“+ 新建变量”、“新建任务”），高度统一定为 `32px`，图文排版严格对齐，主色调统一。

### 2.2 场景 2：卡片与表格行内密集操作（Ghost / Icon Actions）
- **痛点**：原先列表与卡片中混杂着小文字按钮、裸文字字符（`↺` 恢复基准、`✕` 删除环境）或突兀的方框；
- **目标**：行内辅助操作统一收敛为 **26×26px** 或 **28×28px** 的正方形图标容器（Ghost Button）。默认状态克制柔和（透明无背景），Hover 时平滑浮现圆角浅色背景与语义高亮（编辑青、删除红、复制绿、恢复蓝），杜绝视觉噪点。

### 2.3 场景 3：状态性业务触发操作（Capsule Actions）
- **痛点**：安装、应用、当前生效、运行、停止等胶囊按钮形态各异；
- **目标**：统一为标准高度（`26px`）的高清小胶囊，支持加载中（Spinner）、禁用、已生效等统一状态。

### 2.4 场景 4：交互反馈与微动效（Micro-interactions）
- **目标**：统一全局按钮点击时的轻量按压缩放反馈（`transform: scale(0.96)`），赋予产品现代原生软件质感。

## 3. 功能需求详细规范

### FR-01: 全局按钮原子类规范
在 `frontend/src/index.css` 中沉淀标准按钮体系：
- `.btn`: 基础类（flex 居中、防选中文本、平滑过渡动效、按压缩放）；
- `.btn-primary`: 核心实心操作（青色渐变）；
- `.btn-secondary`: 次要线框操作；
- `.btn-ghost`: 幽灵透明按钮；
- `.btn-danger`: 危险操作（默认低调，hover 变红）；
- `.btn-icon`: 严格正方形图标按钮（`26x26px` / `30x30px`）；
- `.btn-capsule`: 紧凑胶囊按钮。

### FR-02: 彻底清除硬编码裸字符
- 全面淘汰模板中的裸字符 `↺`、`✕`、`AA` 等，一律替换为对应的标准 `TechIcon`，并配置规范的 `title` 提示信息。

### FR-03: 各模块视图分步治理落地
- **Phase 1**: 全局 CSS 基建沉淀；
- **Phase 2**: `EnvironmentsView` 环境变量管理视图重构；
- **Phase 3**: `MarketplaceView` 扩展与主题市场视图重构；
- **Phase 4**: `ToolsView` 工具链与 `TasksView` 任务视图重构；
- **Phase 5**: `SettingsView` 设置视图与各模态弹窗（Modals）重构。

---

## 4. 非功能需求与验收标准
- **0 视觉回归**：重构过程中不得破坏现有的交互流程、点击事件及无障碍提示；
- **全端测试全绿**：每一步必须通过 Vitest 单元测试与 Vite 构建；
- **GPG 签名提交**：每一步骤独立执行并单独签署提交。
