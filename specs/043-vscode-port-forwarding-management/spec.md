# 功能规范：VS Code 对齐端口转发与智能云端转发系统 (Port Forwarding Management)

## 1. 背景与目标 (Background & Goals)

在现代化云原生与本地全栈开发中，开发者启动的 Web 应用、微服务、API 网关及后台数据库通常监听于本地宿主或远程容器的各类网络端口（如 Vite 的 5173、Next.js 的 3000、Go/Node API 的 8080/8000、数据库 3306/5432 等）。

在 VS Code 与 GitHub Codespaces 中，「端口 (Ports)」面板是开发者使用最高频的核心组件之一。它不仅能让开发者随时了解当前有哪些网络进程在运行，更提供了自动化发现、远程端口安全中继、浏览器一键预览的能力。

本规范的目标是**深度对齐 VS Code 端口转发体系**，在 UniRTM 底部面板构建工业级的端口管理与智能云端转发系统，实现：
1. **自动转发与手动转发并存**：系统自动探测正在监听的本地服务，并支持用户显式定义持久化转发；
2. **完整的生命周期 CRUD**：创建、查看/状态监测、修改（端口号/本地端口/标签/协议/可见性）、停止转发、重新启动转发与删除端口；
3. **高级端口转发特性**：私有 (Private) 与公开 (Public) 权限切换、本地端口冲突智能自动重映射、终端 URL 自动嗅探与一键打开；
4. **云端开发智能端口转发**：基于端口与进程特征的智能服务类型与图标识别（如 Vite/React/Go/Python/DB）、云端安全公网/局域网反向代理安全链接生成、网络保活与恢复。

## 2. 核心用户故事 (User Stories)

- **US-1 (自动感知与列表洞察)**：作为开发者，在终端运行 `npm run dev` 监听 5173 后，底部「端口」Tab 立即以绿灯 `●` 呈现该端口、正在运行的进程及转发地址，无需手动介入。
- **US-2 (用户手动转发 CRUD)**：作为开发者，我希望点击「添加端口」固定映射远程数据库 3306 或调试端口 9229，即使服务尚未启动也能持久化保留（空心圆 `○`），并能随时编辑其标签、停止或删除。
- **US-3 (快捷访问与集成交互)**：作为开发者，在端口行中能一键复制地址、在编辑器内置浏览器或外部系统浏览器中快速打开预览。
- **US-4 (高级特性与冲突解决)**：当目标本地端口被占用时，系统智能分配相邻可用端口；支持切换 HTTP/HTTPS 协议与公开/私有访问控制。
- **US-5 (云端智能服务识别)**：在云端或容器开发时，系统能根据端口号与命令特征智能打上标签（如 `Vite Dev Server`、`MySQL Database`、`Jupyter Lab`），并自动生成安全预览链接。

## 3. 功能需求矩阵 (Functional Requirements)

### 3.1 端口模型与状态机 (FR-1)
- **FR-1.1 (状态指示)**：
  - `active`（实心绿灯 `●`）：对应端口正处于系统 `LISTEN` 状态且转发中继正常就绪。
  - `inactive`（空心圆 `○`）：已配置转发项但当前无本地服务响应，或已被用户手动“停止转发”。
- **FR-1.2 (来源分类)**：
  - `auto`（自动转发）：随系统进程监听动态生成，服务关闭时自动清理。
  - `user`（用户转发）：用户主动添加，持久化保存于工作区配置中。
- **FR-1.3 (访问可见性)**：
  - `private`（私有）：仅限当前认证会话或本机回路（127.0.0.1）访问。
  - `public`（公开）：允许局域网或云端公网安全隧道访问。

### 3.2 端口管理 CRUD 操作 (FR-2)
- **FR-2.1 (创建 - Create)**：支持通过「添加端口」按钮或终端自动侦测创建转发项；可指定远程端口、本地映射端口、协议类型（HTTP/HTTPS）及标签备注。
- **FR-2.2 (查看 - Read)**：底部面板表格化展现：状态图标、端口号、标签名称、转发地址、进程名/命令行、来源、访问控制与快捷操作。
- **FR-2.3 (修改 - Update)**：支持内联或弹窗编辑端口标签（Label）、本地映射端口（Local Port）、协议与公开/私有属性。
- **FR-2.4 (停止/启动 - Stop/Start)**：支持在不删除配置的前提下，一键临时“停止转发”，以及后续“恢复转发”。
- **FR-2.5 (删除 - Delete)**：从工作区中彻底移除该端口转发项。

### 3.3 高级转发特性 (FR-3)
- **FR-3.1 (终端 URL 智能嗅探)**：监听集成终端（Xterm）输出流，实时捕获诸如 `http://localhost:XXXX` 或 `http://127.0.0.1:XXXX`，自动添加到转发列表并触发 Toast 提示。
- **FR-3.2 (本地端口冲突重映射)**：如果待转发的目标本地端口已被其他应用占用，自动递增寻找可用端口（如 8080 已被占用则自动重映射到 8081），并直观显示映射关系 `8080 -> 8081`。
- **FR-3.3 (一键多端预览)**：支持「在内置浏览器中打开」、「在系统默认浏览器中打开」、「复制转发地址」。

### 3.4 云端开发智能端口转发 (FR-4)
- **FR-4.1 (智能服务指纹识别)**：
  - 内置常见技术栈端口与进程签名规则库（如 Vite 5173、Next.js 3000、Webpack 8080、Django 8000、FastAPI 8000、Spring Boot 8080、MySQL 3306、Postgres 5432、Redis 6379、MongoDB 27017 等）。
  - 自动为端口分配精准的技术栈图标（`TechIcon`）与友好的默认标签。
- **FR-4.2 (云端安全反向代理预览 URL)**：
  - 在云端开发/容器环境中，自动生成基于 UniRTM 网关的统一安全预览路径（如 `/api/ports/preview/:port/` 或带临时签名 Token 的公网链接），解决云端开发直接访问 127.0.0.1 无法触达的痛点。
- **FR-4.3 (网络保活与心跳自愈)**：
  - 定时轮询与状态同步，云端网络重连后自动恢复活跃端口状态。

## 4. 非功能性需求 (Non-Functional Requirements)

- **NFR-1 (极低资源开销)**：端口扫描必须在系统底层高效执行（Linux 直接解析 `/proc/net/tcp*` 或轻量执行 `ss`），避免频繁创建重量级子进程消耗 CPU。
- **NFR-2 (多平台兼容)**：支持 Linux、macOS 与 Windows。
- **NFR-3 (双端一致性)**：Go 生产后端（`cmd/64.ui.go`）与 Vite 开发环境（`frontend/vite.config.ts`）提供完全一致的 `/api/ports/*` 接口表现。
- **NFR-4 (多语言完备)**：所有界面文本覆盖全部 53 种国际化语言。
