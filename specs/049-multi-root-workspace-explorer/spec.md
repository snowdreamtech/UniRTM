# 规范文档：多根工作区与文件浏览器工作区管理系统 (Specification)

## 1. 业务背景与问题分析 (Problem Statement)

在现代大型工程协作与模块化微服务开发中，开发者常常需要同时处理多个独立代码库或子工程。
现代 IDE（以 VS Code 为代表）提供了原生的**多根工作区（Multi-root Workspaces）**能力：
- 允许在同一个文件浏览器侧边栏中挂载并浏览多个顶级项目文件夹；
- 用户可以便捷地通过右键菜单将子文件夹或本地外部文件夹“添加到工作区”；
- 也可以右键任意顶级根文件夹“将文件夹从工作区删除”（仅解除引用，不伤及磁盘物理文件）。

### 当前 UniRTM 文件浏览器现状与痛点：
1. **单一根目录局限**：目前文件浏览器仅固定加载单个根目录（单一 `tree` 节点），无法支持多项目多模块同屏并存；
2. **缺乏右键工作区管理菜单**：右键菜单中没有“将文件夹添加到工作区...”与“将文件夹从工作区删除”命令，无法满足复杂的工程管理需求。

---

## 2. 核心原则与设计目标 (Design Goals)

1. **深度对齐 VS Code 原生体验**：
   - 右键任意文件夹，提供“将文件夹添加到工作区...”选项；
   - 对属于工作区根节点（Root Folders）的文件夹，提供“将文件夹从工作区删除”选项；
   - 界面布局、层级关系与右键菜单结构与 VS Code 保持一致。
2. **前后端协同持久化**：
   - 记录并持久化工作区挂载的文件夹根路径列表；
   - 页面刷新、切换作用域或重新打开时，多根工作区状态完整复原。
3. **数据安全防护**：
   - “将文件夹从工作区删除”严格限定为“解除工作区管理索引”，绝对不执行物理文件的底层删除。
4. **全语言与高可靠性**：
   - 覆盖 53 种国际化语言包；
   - 全量覆盖单元测试，确保类型检查与打包 0 错误。

---

## 3. 详细功能规范 (Functional Requirements)

### 3.1 右键菜单项规范
| 菜单项名称 | 触发节点条件 | 交互行为 | 安全与提示 |
| :--- | :--- | :--- | :--- |
| **将文件夹添加到工作区...** | • 任何文件夹节点<br>• 文件浏览器空白背景处 | 弹出路径添加对话框，支持输入本机路径或确认将选中的子文件夹作为独立根添加 | 添加成功后，左侧树立即呈现该独立根节点 |
| **将文件夹从工作区删除** | • 仅在当前属于“多工作区根节点”的文件夹上呈现 | 弹出确认提示后，将该根从多根列表中移除 | 明确提示“仅从工作区移出，不会删除磁盘上的任何文件” |

### 3.2 树视图多根呈现
- **单根模式（默认）**：若仅有 1 个根目录，维持简洁的单根展示或原汁原味的工程标题；
- **多根模式（Multi-root）**：
  - 顶部主标题显示 `工作区 (N 个文件夹)`；
  - 列表中呈现 N 个顶级根文件夹节点，每个节点拥有独立的名称、折叠箭头、新建/刷新快捷按钮及子树结构；
  - 树操作（展开、折叠、新建文件、删除文件、搜索过滤）无缝支持跨根定位。

### 3.3 持久化与同步
- 后端提供 `/api/workspace/roots` 读取与更新接口；
- 前端 `useWorkspace` 与 `useFileTree` 响应式同步多根节点数据。
