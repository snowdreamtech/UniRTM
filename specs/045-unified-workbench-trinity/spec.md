# 功能规范：文件管理器、编辑器与源代码管理三位一体协同系统 (Spec)

## 1. 概述与背景
在现代云原生与本地集成开发环境（IDE，如 VS Code）中，**文件管理器 (Explorer)**、**代码编辑器 (Editor)** 与 **源代码管理 (Source Control / SCM)** 构成了开发者日常工作流的核心“三位一体”铁三角。
目前 UniRTM 虽然具备了上述三个模块，但彼此之间存在明显的视图割裂、状态异步以及操作链条断裂：
- SCM 的 Diff 视图独立于主编辑器 Tab，审查变动时需频繁切换页面视口；
- 编辑器 Tab 缺少 Git 状态色彩提示（如已修改黄色 M、新增绿色 U 等）；
- 文件管理器、SCM 列表与编辑器之间缺乏直达定位（Reveal in Explorer / Go to File）；
- 文件管理器右键菜单缺乏直接暂存 (Stage)、放弃更改 (Discard) 等 Git 上下文动作。

本特性的目标是彻底打通三者间的数据壁垒与交互断点，实现视图统一、双向定位、行级感知与上下文动作融合。

---

## 2. 核心用户故事 (User Stories)

### 故事 1：统一 Diff 审查体验
- **作为** 一名代码审阅者或开发者，
- **我希望** 在 SCM 列表或文件树中点击差异对比时，能直接在主编辑器中打开一个 Diff 标签页（如 `main.go (工作树 ↔ HEAD)`），
- **以便于** 我可以同时保留普通编辑 Tab 和 Diff Tab，随时自由并列对照与无缝切换。

### 故事 2：全链路双向定位与感知
- **作为** 一名在大型项目中开发的工程师，
- **我希望** 在 SCM 列表中能一键「在文件管理器中定位 (Reveal in Explorer)」，在文件管理器点击文件时能自动切入编辑器对应 Tab，
- **以便于** 我在面对繁多嵌套目录时秒级感知文件物理位置与变动全貌。

### 故事 3：Tab 与行级实时 Git 状态反馈
- **作为** 一名正在编写代码的工程师，
- **我希望** 编辑器 Tab 标题呈现 Git 变动色与标记（M / U），且代码行号旁能清晰看到未提交的增量装饰（绿色新增、蓝色修改、红色删除），
- **以便于** 我不用离开编辑器就能确切了解自己修改了哪些逻辑。

### 故事 4：就近触达的上下文动作
- **作为** 一名习惯高效操作的开发者，
- **我希望** 在文件管理器右键任意已变动文件时，能直接执行「暂存更改」、「放弃更改」或「对比修改」，
- **以便于** 我无需特意切换到 SCM 视图即可快速管理提交批次。

---

## 3. 验收标准 (Acceptance Criteria)

1. **统一 Diff 标签页**：
   - 在 SCM 变更列表点击文件或点击对比按钮，主编辑器打开/聚焦对应的 Diff 标签页，支持正常关闭、中键关闭及拖拽重排；
   - Diff 标签页支持 Side-by-Side (双列) 与 Inline (单列) 切换。
2. **Tab 视觉状态增强**：
   - 编辑器 Tab 标题同步反映 Git 变动色（修改态黄色文字与 M 徽标、新增态绿色文字与 U 徽标）；
   - 未保存脏状态（白色圆点 `●`）与 Git 变动状态层次分明、互不干扰。
3. **双向 Reveal 联动**：
   - SCM 变更列表项提供「在资源管理器中揭示」按钮及右键项；
   - 触发后，文件管理器自动递归展开对应的所有父级文件夹，滚动使目标可见并予以平滑高亮。
4. **上下文动作融合**：
   - 文件管理器右键菜单根据当前文件节点的 Git 状态（已修改、未跟踪、已暂存等）动态提供 Git 操作组（暂存、取消暂存、放弃更改、对比修改）；
   - 执行操作后，文件管理器与 SCM 列表均毫秒级响应更新。
5. **多语言与质量规范**：
   - 新增文案完整适配所有 53 种语言；
   - 前端 Vitest 单元测试全绿，类型检查与生产构建打包 0 报错。
