# 功能规范：文件管理器、编辑器与源代码管理三位一体协同系统 (Spec)

## 1. 概述与背景
在现代云原生与本地集成开发环境（IDE，如 VS Code）中，**文件管理器 (Explorer)**、**代码编辑器 (Editor)** 与 **源代码管理 (Source Control / SCM)** 构成了开发者日常工作流的核心“三位一体”铁三角。
过去 UniRTM 虽然具备了上述三个模块，但彼此之间存在明显的视图割裂、状态异步以及操作链条断裂：
- SCM 的 Diff 视图独立于主编辑器 Tab，审查变动时需频繁切换页面视口；
- 编辑器 Tab 缺少 Git 状态色彩提示（如已修改黄色 M、新增绿色 U 等）；
- 文件管理器、SCM 列表与编辑器之间缺乏直达定位（Reveal in Explorer / Go to File）；
- 文件管理器右键菜单缺乏直接暂存 (Stage)、放弃更改 (Discard) 等 Git 上下文动作；
- 外部文件重命名或删除时，编辑器已打开标签页无法感知并平滑迁移；
- 缺乏微观行级的 Git 增量指示与局部代码块暂存/回退能力；
- 树形目录繁杂时无法快速聚焦修改范围，折叠文件夹无法直观看到内部变更总数。

本特性的目标是彻底打通三者间的数据壁垒与交互断点，实现视图统一、双向定位、行级感知、就近操作、聚焦排查与生命周期状态深度闭环。

---

## 2. 核心用户故事 (User Stories)

### 故事 1：统一 Diff 审查体验
- **作为** 一名代码审阅者或开发者，
- **我希望** 在 SCM 列表或文件树中点击差异对比时，能直接在主编辑器中打开一个 Diff 标签页（如 `main.go (工作树 ↔ HEAD)`），
- **以便于** 我可以同时保留普通编辑 Tab 和 Diff Tab，随时自由并列对照与无缝切换。

### 故事 2：全链路双向定位与感知
- **作为** 一名在大型项目中开发的工程师，
- **我希望** 在 SCM 列表中能一键「在文件管理器中定位 (Reveal in Explorer)」，在文件管理器点击文件时能自动切入编辑器对应 Tab，
- **以便于** 我在面对繁多嵌套目录时秒级感知文件物理位置与变动全貌。

### 故事 3：Tab 与行级实时 Git 状态反馈
- **作为** 一名正在编写代码的工程师，
- **我希望** 编辑器 Tab 标题呈现 Git 变动色与标记（M / U），且代码行号旁能清晰看到未提交的增量装饰（绿色新增、蓝色修改、红色删除），
- **以便于** 我不用离开编辑器就能确切了解自己修改了哪些逻辑。

### 故事 4：就近触达的上下文动作
- **作为** 一名习惯高效操作的开发者，
- **我希望** 在文件管理器右键任意已变动文件时，能直接执行「暂存更改」、「放弃更改」或「对比修改」，
- **以便于** 我无需特意切换到 SCM 视图即可快速管理提交批次。

### 故事 5：生命周期与外部变动深度联动
- **作为** 一名重构代码的工程师，
- **我希望** 在文件树重命名或删除文件/目录时，编辑器中已打开的对应标签页自动无缝平滑更新路径或优雅关闭；在 SCM 执行放弃或暂存时，编辑器内存脏状态与外部文件状态智能同步，
- **以便于** 避免旧路径文件错乱覆盖或出现数据丢失。

### 故事 6：行级差异预览与就地回滚及暂存
- **作为** 一名专注编码的开发者，
- **我希望** 点击行号槽的 Git 差异条时能浮出 Inline Diff 气泡卡片，不仅能直观比对改动前的原始内容，还能一键「还原此块 (Revert Chunk)」或「暂存此块 (Stage Chunk)」，
- **以便于** 在编辑器中完成原子粒度的代码微操，而无需切换到 Diff 视图。

### 故事 7：文件树 Git 聚焦与被忽略文件识别
- **作为** 一名排查复杂分支修改的工程师，
- **我希望** 能在文件树顶栏一键切换「Git 聚焦模式 (Git Focus)」，树中仅保留包含变动的文件及其父级目录链；同时对 `.gitignore` 规则匹配的文件进行半透明灰显，
- **以便于** 快速理清改动全貌，避免海量无关目录干扰视线。

### 故事 8：文件树折叠目录的变更计数徽标
- **作为** 一名浏览大型工程多级嵌套目录的开发者，
- **我希望** 当父文件夹处于折叠状态时，行尾能显示内部已修改/新增文件的计数气泡（如 `+3`），
- **以便于** 即使目录未展开，也能迅速洞察各个功能模块的代码演进热度。

### 故事 9：编辑器状态栏全局分支穿透联动
- **作为** 一名在多分支协作的工程师，
- **我希望** 在编辑器底部状态栏始终能看到当前 Git 分支名与工作区变更统计计数，点击分支名可直接呼出 SCM 面板并聚焦，
- **以便于** 随时确认上下文分支与提交流程。

## 3. 验收标准 (Acceptance Criteria)

1. **统一 Diff 标签页**：
   - 在 SCM 变更列表点击文件或点击对比按钮，主编辑器打开/聚焦对应的 Diff 标签页，支持正常关闭、中键关闭及拖拽重排；
   - Diff 标签页支持 Side-by-Side (双列) 与 Inline (单列) 切换。
2. **Tab 视觉状态增强**：
   - 编辑器 Tab 标题同步反映 Git 变动色（修改态黄色文字与 M 徽标、新增态绿色文字与 U 徽标）；
   - 未保存脏状态（白色圆点 `●`）与 Git 变动状态层次分明、互不干扰。
3. **双向 Reveal 联动**：
   - SCM 变更列表项提供「在资源管理器中揭示」按钮及右键项；
   - 触发后，文件管理器自动递归展开对应的所有父级文件夹，滚动使目标可见并予以平滑高亮。
4. **上下文动作融合**：
   - 文件管理器右键菜单根据当前文件节点的 Git 状态（已修改、未跟踪、已暂存等）动态提供 Git 操作组（暂存、取消暂存、放弃更改、对比修改）；
   - 执行操作后，文件管理器与 SCM 列表均毫秒级响应更新。
5. **生命周期与重命名安全迁移**：
   - 文件/目录重命名或删除后，已打开的编辑器 Tab 自动同步重定向至新路径或提示安全关闭，无内存泄露与脏数据残留。
6. **行级 Git Gutter 与 Inline Peek 微操**：
   - Monaco 编辑器行号槽实时呈现绿（新增）、蓝（修改）、红（删除）指示条；
   - 点击指示条呼出 Inline Diff Peek 浮窗，支持一键「还原此块」与「暂存此块」，操作后行号槽与 Git 状态无缝刷新。
7. **Git 聚焦模式与 Gitignore 过滤**：
   - Explorer 提供 Git Focus 按钮，激活时仅剪裁展示修改项及其链路；对 `.gitignore` 文件给予置灰与清晰状态标识。
8. **折叠目录变更计数徽标 (Bubble Count)**：
   - 处于折叠状态的父目录，当其子孙包含变动时，行尾呈现轻量气泡统计徽标（展示内部变更数），展开后优雅退场或弱化。
9. **状态栏分支与工作区穿透**：
   - 编辑器底栏常驻显示当前分支名称与变更总计，点击可无缝穿透切入 SCM 视图。
10. **多语言与端到端质量规范**：
    - 新增文案完整适配所有 53 种语言包；
    - 单元测试 100% 通过，类型检查与生产环境构建 0 报错。
