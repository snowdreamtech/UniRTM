# 规范文档：开发环境工具链左侧栏状态折叠分组面板 (Specification)

## 1. 业务背景与问题分析 (Problem Statement)

在现代工程协作开发中，项目的运行环境与工具链（如 Node.js, Go, Python, Rust, Bun 等）可能处于不同生命周期状态：
- **待安装（Missing / Pending Install）**：项目或用户在 `.unirtm.toml` 中锁定了特定版本，但当前开发者本地尚未安装，急需安装以保证环境可用；
- **可升级（Upgradable）**：工具已安装，但上游检测到更高可用版本；
- **已就绪 / 已安装（Ready / Installed）**：配置的版本已在本地正确安装并就绪。

### 当前现状与痛点：
1. **列表平铺难以感知重点**：目前左侧边栏（`SidebarPanel.vue`）以单一扁平列表罗列所有工具，当工程中存在尚未安装或可升级的工具时，用户无法一目了然区分哪些工具急需处理，必须在主视图内点开或逐一查找；
2. **缺乏状态聚合能力**：缺少类似 VS Code 侧边栏原生的折叠分组（Accordion）设计，无法按状态动态分组。

---

## 2. 核心原则与设计目标 (Design Goals)

采纳 **方案 A：VS Code 折叠分组面板（Accordion）** 规范：
1. **层级分明，按状态自适应分组**：
   - **⚠️ 待安装 (N)**：仅当 $N > 0$ 时显示在最顶部，默认展开，采用琥珀色警示样式；
   - **🟢 可升级 (N)**：仅当 $N > 0$ 时展示，默认展开，采用绿色升级圆点与徽标；
   - **已就绪 / 已安装 (N)**：收纳所有正常就绪的工具，支持自由折叠与展开；
2. **极简低噪音原则**：
   - 当待安装工具数为 0 时，完全隐藏“待安装”分组，不干扰正常开发；
   - 当可升级工具数为 0 时，完全隐藏“可升级”分组；
3. **即时联动与搜索适配**：
   - 顶部搜索框过滤时，各分组实时同步过滤结果与计数；
   - 点击任一工具项无缝跳转至工具详情页；
4. **全语言 53 种国际化与单元测试保障**：
   - 提供 53 种语言包的本地化文案，确保各组别标题在各语种下均自然对齐；
   - 单元测试覆盖分组计算与折叠交互。

---

## 3. 详细功能规范 (Functional Requirements)

### 3.1 分组结构与显示规则
| 分组标识 | 显示触发条件 | 默认展开状态 | 视觉与徽标风格 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **⚠️ 待安装 (`missing`)** | 当前匹配到 `missing` 状态的工具数量 $N > 0$ | 默认展开 (`true`) | 琥珀金/黄色警示警告图标 `⚠️`，警告计数气泡 | 紧急级别最高，位于最顶部，一眼可见 |
| **🟢 可升级 (`upgradable`)** | 当前匹配到 `upgradable` 状态的工具数量 $N > 0$ | 默认展开 (`true`) | 绿色小圆点 `🟢`，升级计数徽标 | 提示有新版本可用 |
| **已就绪 / 已安装 (`ready`)** | 无论 $N$ 是否为 0 均展示（若无其他组则独占） | 默认展开 (`true`)，支持折叠 | 默认文本与主题色计数气泡 | 展示所有工作正常、无需干预的环境 |

### 3.2 交互行为规范
1. **折叠与展开**：
   - 点击分组头部（含旋转箭头 Twistie 与计数 Pill），独立切换该分组的展开/折叠状态；
2. **搜索过滤响应**：
   - 在左侧栏输入关键字时，各分组内仅展示命中关键字的工具项，分组头部的计数 $(N)$ 动态反映过滤后的命中数；
   - 若某分组在搜索后命中数为 0，则该分组临时隐藏；
3. **点击导航**：
   - 点击任一工具项时，保持当前选中高亮，并在右侧主视图定位该工具详情。
